# Mapa integrado — corrección 2026-10-15

Ámbito SMARTVEST, aislado. Reporte de John: llega ubicación pero el recuadro no muestra el mapa de forma persistente.

## Diagnóstico y criterio

El prototipo de mapa presente en el árbol local descargaba Leaflet desde un CDN y regeneraba el HTML cuando cambiaban las coordenadas. Además, el bloque GPS se retiraba cuando una lectura perdía fijación. No se atribuye el fallo físico a una causa única sin reproducirlo en el teléfono.

Aceptación: mapa visible dentro de Monitoreo; una lectura mueve un único marcador sin navegar ni remontar el documento; respeta zoom/desplazamiento del cuidador, permite centrar; pérdida temporal de GPS conserva el último punto de ese dispositivo con aviso. Sin datos válidos no inventa coordenadas. Descarga fallida muestra error y permite reintentar. Abrir otra app es opcional.

## Implementación

- Motor Leaflet 1.9.4 y CSS incluidos en el APK; no depende del CDN al abrir. Fuentes oficiales verificadas por SHA-256 antes de normalizar saltos y espacios finales de CSS/licencia. [Distribución oficial](https://leafletjs.com/download.html). Licencia BSD incluida en assets.
- WebView conserva el documento y recibe solo coordenadas numéricas validadas y color hexadecimal. Sin puentes JavaScript nativos, acceso a archivos, contenido arbitrario ni navegación web libre. CSP restringe las imágenes a las teselas y datos locales.
- Cartografía HTTPS de OpenStreetMap, atribución visible y enlazable, User-Agent SmartVest identificable y caché normal del navegador. No hay precarga ni descarga para uso offline. [Política del servicio](https://operations.osmfoundation.org/policies/tiles/). La cartografía nueva requiere conexión y el proveedor puede no estar disponible.
- Último punto conservado únicamente en memoria de pantalla y asociado a `deviceId`; no se reutiliza entre dispositivos ni cuentas. Sin etiquetas personales, tokens o datos de perfil enviados al motor del mapa.
- El mapa normal se mantiene fuera de la condición SOS. La integración del prototipo local de SOS utiliza el mismo motor; sus otros cambios no forman parte de este commit.

## Verificación

## Corrección posterior — mapa sin fijación inicial

John reportó que seguía sin ver el mapa en la versión 39. Se identificó un defecto adicional: `LocationMapCard` solo componía la WebView cuando ya tenía una coordenada válida. En el Redmi se había observado previamente “Esperando una ubicación GPS válida”; por tanto esa pantalla no llegaba a crear el mapa. No se atribuye este comportamiento al teléfono.

La versión 40 / 1.3.8-m1-map-visible crea la cartografía al abrir el componente, con vista general mundial y sin marcador. Centrar y abrir otra aplicación requieren una ubicación válida. Cuando llega el primer GPS se agrega el marcador y se enfoca esa posición, conservando la misma instancia de mapa. Al cambiar a un dispositivo sin ubicación se retira el marcador anterior y se vuelve a la vista general.

La regresión del navegador ahora inicia sin coordenadas: exige teselas visibles, cero marcadores y centrado deshabilitado antes de enviar el primer GPS. También comprueba limpiar la posición y recuperarla sin recrear el mapa. Pruebas con teselas PRUEBA interceptadas, sin usar posiciones personales.

ADB no detectaba el Redmi al comenzar esta segunda revisión; falta instalar la versión 40 y comprobar la cartografía real en el teléfono. La instalación física anterior fue la versión 39, sin renderizado físico acreditado.
